# clio MCP Creatio C# platform checks

## Scope
Read this when you are about to write, change or review server-side C# for Creatio: a script task, a configuration web service, an entity or application listener, a query executor, a background job, a custom MCP action or any other source-code schema. Work that writes no C# (pages, the process designer, data, settings) does not need it, and neither do tests or client tools that run outside Creatio.

This guide owns the seven checks below. The patterns around them stay with their owners: `websocket-messaging` (messages to users), `configuration-webservice` (the service class and its `Func<UserConnection>` accessor), `sys-settings` (`SecureText` values), `sys-setting` (reading settings in C#), `record-permission-extensions` (record rights), `virtual-entities` (rights in a query executor), `assembly-package` (background jobs), `server-to-server-oauth` (OAuth clients), `esq-filters-backend` (query filters).

## How to apply
- Writing: produce the correct form from the start. Do not leave a check for a later review.
- Reviewing: search the code for each signature and report a hit only when the whole signature holds, its condition included. Give the file and line, the consequence and the correct form.
- Code that already has the correct form gets no finding.
- Read locks are not a check: on MS SQL, `Select` and `EntitySchemaQuery` already read with `NOLOCK` by default. Do not add `Hints.NoLock` and do not report its absence.

## Checks
| # | Signature | Why it is a defect on Creatio | Correct form |
|---|---|---|---|
| 1 | `AddAllSchemaColumns()` on an `EntitySchemaQuery` | the query reads every column of the schema for every row and joins the table of every lookup for its display value | `AddColumn("<column path>")` for each column the code reads. When the code saves the entity it loaded, also each required column: `Save()` throws `RequiredColumnsEmptyValuesException` for a required column that was not loaded |
| 2 | `StartTransaction()` with no `RollbackTransaction()` in a catch, or on a `DBExecutor` that is never disposed | the open transaction keeps its locks and blocks other sessions | `using (DBExecutor dbExecutor = UserConnection.EnsureDBConnection())`, then `StartTransaction()`, `CommitTransaction()` on success and `RollbackTransaction()` in the catch, then rethrow: inside a transaction an outer level started, both calls do nothing and the outer level decides. Only the dispose that closes the outermost level rolls back a transaction still open, so do not rely on it |
| 3 | `MsgChannelUtilities.PostMessageToAll(`, or `PostToAll(` on a `MsgChannelManager` or `IMsgChannelManager`, for a message meant for one user, or with no operation-permission check before it. `MsgChannelUtilities.PostMessage(UserConnection, ...)` posts to the current user only and is not a broadcast | every user connected to the environment receives the message and its data | a message for one user goes to that user's channel, built as `websocket-messaging` shows (a JSON body: a Freedom UI page drops any other). Keep a broadcast for an announcement every user may see, behind an operation-permission check |
| 4 | code that runs outside a request (a job, a thread, a task) and relies on `HttpContext`, or a `static` field that holds a `UserConnection` | outside a request there is no `HttpContext`; a static connection serves one user's identity and rights to every later caller | a web service inherits `BaseService` and uses its `UserConnection` (`configuration-webservice`). A background job uses the `UserConnection` passed to `Execute` (`assembly-package`). Through DI, inject a `Func<UserConnection>` accessor, never the connection itself |
| 5 | a credential or key in a literal, a config entry or a plain-text setting | anyone who reads the code, the package or the configuration gets it | a `SecureText` system setting (`sys-settings`) read through `SysSettings` (`sys-setting`) |
| 6 | `Supervisor` / `Supervisor` or another default credential | full administrator access for anyone who reaches the host. `localhost` is no exception: shipped code runs on the customer's server | a dedicated user or an OAuth client with only the rights the integration needs; credentials as in check 5 |
| 7 | in an operation done for a user: `UseAdminRights = false` on a query or entity, a raw `Select`, `Update` or `Delete` that does not apply the caller's rights itself, or `SystemUserConnection` in place of the caller's connection | the user's record rights are not applied, so the user reads or changes records hidden from them | an `EntitySchemaQuery` or `Entity` on the caller's `UserConnection` with the default `UseAdminRights = true`, which applies the user's record rights. Keep `false`, raw queries and `SystemUserConnection` for system work that never returns or changes records on a user's behalf. A raw query that enforces the caller's rights itself and fails closed (`virtual-entities`) and a `Select` inside the condition a record-permission extension returns (`record-permission-extensions`) are not hits |

## Verification boundary
Read in the Creatio platform source, the same in trunk commit 89269efe (2026-11-18) and release 10.0.0.858 (commit c5214831): the `UseAdminRights` default and the raw `Select`, `Update` and `Delete` that check no rights, the `NOLOCK` a `Select` renders on MS SQL by default, the lookup joins of `AddAllSchemaColumns`, the required-column check of `Entity.Save`, the transaction depth of `DBExecutor`, `PostToAll` on `IMsgChannelManager`, `BaseService.UserConnection` taken from the session or, for an OAuth client, from the request, and the `SysSettings` read methods. `MsgChannelUtilities` was read in the `CrtCoreBase` package of Creatio 10.2.1161 on .NET Framework and MS SQL. Runtime and database were not measured: none of the seven ran on a stand.
